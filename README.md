# 放疗患者管理

放疗科患者管理工具。**离线优先、数据只存本机**的 PWA（渐进式 Web 应用），
可安装到手机桌面，断网也能使用。

---

## 文件清单

| 文件 | 作用 | 必需 |
|---|---|---|
| `index.html` | 应用本体（单文件，含全部界面与逻辑） | 是 |
| `manifest.webmanifest` | PWA 清单：应用名、图标、启动方式 | 是 |
| `sw.js` | Service Worker：离线缓存 | 是 |
| `icon.svg` / `icon-192.png` / `icon-512.png` | 应用图标（Android / 浏览器） | 是 |
| `apple-touch-icon.png` / `icon-180.png` | iOS 桌面图标（iOS 只认 PNG） | 是 |
| `.nojekyll` | 告知 GitHub Pages 跳过 Jekyll 处理 | 是 |
| `README.md` | 本说明文档（可选，仅仓库展示用） | 否 |

> 共 10 个文件。其中 `.nojekyll` 是空文件，作用只是开关，内容为空属正常。

## 一、部署到 GitHub Pages

### 1. 注册 / 登录 GitHub

访问 <https://github.com> 注册账号（免费）。

### 2. 新建仓库

右上角 **+** → **New repository**

- **Repository name**：填 `你的用户名.github.io`
  （例如用户名是 `zhangsan`，就填 `zhangsan.github.io`）
  > 这样得到的地址是 `https://zhangsan.github.io/`，与参考站形式一致。
  > 若填其他名字（如 `radiotherapy`），地址会变成 `https://zhangsan.github.io/radiotherapy/`，
  > 功能完全相同，只是路径多一层。
- **Public**：必须选公开（私有仓库的 Pages 需要付费）
- 不要勾选 "Add a README file"
- 点 **Create repository**

### 3. 上传文件

在仓库页面点 **uploading an existing file**（或 Add file → Upload files），
把本目录下**全部 10 个文件**拖进去（注意：`.nojekyll` 是隐藏文件，需在文件管理器里
开启"显示隐藏文件"才能看到；若实在找不到，跳过它也不影响运行）。

> 也可以把整个文件夹拖进去；关键是 `index.html` 必须位于仓库根目录。

填个提交信息（如 `first deploy`），点 **Commit changes**。

### 4. 开启 Pages

仓库页 → **Settings** → 左侧 **Pages**

- **Source**：选 `Deploy from a branch`
- **Branch**：选 `main`，目录选 `/ (root)`
- 点 **Save**

等待 1~2 分钟，刷新页面，顶部会出现绿色提示与网址：

```
https://你的用户名.github.io/
```

> ⚠️ 若仓库名不是 `用户名.github.io`，网址会是
> `https://你的用户名.github.io/仓库名/`

## 二、在手机上安装

> **前提**：本应用需要 HTTPS 才能离线缓存与安装。GitHub Pages 自带 HTTPS，满足条件。

### Android（Chrome / Edge）

1. 用浏览器打开上面的网址
2. 菜单（右上角 ⋮）→ **安装应用** 或 **添加到主屏幕**
3. 桌面出现「放疗管理」图标，点开即为独立应用（无浏览器地址栏）

### iOS（必须用 Safari）

1. **用 Safari 打开**（Chrome for iOS 不支持添加到桌面）
2. 点底部 **分享** 按钮 → **添加到主屏幕**
3. 桌面出现图标

> ⚠️ **重要**：从桌面图标打开 与 用 Safari 打开同一个网址，是**两个独立的存储空间**，
> 数据互不相通。请固定用桌面图标进入，不要混用。

## 三、跨设备同步数据

数据存在手机本地（localStorage），不经过任何服务器。换设备时用**备份文件**搬运。

### 操作步骤

**在设备 A（导出）**
1. 右上角 **⋯** → **导出完整备份（JSON）**
2. 文件会保存到「文件」App 或直接转发到微信 / 邮件

**在设备 B（导入）**
1. 把 JSON 文件传到设备 B（微信传文件、邮件附件、网盘均可）
2. 右上角 **⋯** → **导入备份恢复**
3. 选择 **合并导入**（推荐，保留两台设备各自新增的患者与记录）
   或 **覆盖导入**（完全用备份文件替换本机数据）

### 两种导入方式的区别

| 方式 | 行为 | 适用场景 |
|---|---|---|
| **合并导入** | 按患者去重合并，两边新增的患者与记录都保留 | 两台设备各自录过数据，需要合到一起 |
| **覆盖导入** | 本机数据被备份文件完全替换 | 换新手机，把旧手机数据完整搬过来 |

> 无论哪种，导入前建议先导出一次本机备份作为保险。

### 什么时候需要重复同步

本方案**没有自动同步**：设备之间不会实时保持一致。
需要你在换设备前手动执行一次「导出 → 导入」。

如果希望「换台设备登录就看到同一批患者」，那需要改用带服务器的云端方案。

## 四、更新应用（修改功能后重新发布）

### 数据会不会丢？

**不会。** 应用内建了三层数据保护，更新版本后原有患者数据完整保留：

| 保护 | 说明 |
|---|---|
| **格式自动迁移** | 老版本的数据结构会自动转换成新格式。老字段（如「开始日期」的旧字段名）、旧的逐次治疗记录、旧的患者状态（「暂停」「随访中」）都会自动对应到新结构，不丢失 |
| **迁移前自动备份** | 检测到需要转换格式时，先把**原始数据**另存一份（保留最近 3 份），万一转换有问题可在「设置」里一键回退 |
| **读取失败时禁止写入** | 若本机数据损坏读不出来，应用会**暂停保存功能**并提示你先导出原始数据，绝不用空数据覆盖你的记录 |

> 界面上不会有任何"数据迁移中"的干扰，打开即用。

### 发布步骤

1. 把新的 `index.html`（及其他改动过的文件）上传覆盖到仓库
2. **同步递增 `sw.js` 里的 `CACHE` 版本号**，例如 `radiotherapy-v4` → `radiotherapy-v5`

> 为什么必须改版本号：浏览器通过版本号判断缓存是否过期。
> 不改的话，已安装到桌面的用户可能长时间停留在旧版本。

本应用的 Service Worker 对 HTML 采用**网络优先**策略，
改完并递增版本号后，用户下次打开即为最新版（离线时仍用缓存）。

### 回退到更新前的数据

如果更新后发现数据异常：
**⋯ → 设置** → 找到「更新前自动备份」→ 点一下即可回退到更新前的状态。

## 五、注意事项

- **数据安全**：数据只存在设备本地。请**定期导出 JSON 备份**——
  长期不打开应用时，iOS 可能清理站点存储；清理浏览器数据、卸载浏览器也会清除数据。
- **微信内打开**：微信内置浏览器无法"添加到桌面"，请引导用户"在浏览器中打开"。
- **地址不要变**：浏览器按域名隔离存储。更换网址（含 http/https、有无 www）
  会导致读不到原有数据，看起来像"数据丢了"。
- **合规**：本方案不上传任何患者数据到服务器，页面外壳公开可达但内容为空。
  若医院对公网可达有要求，应改为院内网部署。
