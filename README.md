# 放疗患者管理

放疗科患者管理工具。离线优先的单文件 PWA，**数据只存在本机**，不上传任何服务器。

## 访问

<https://kyouyama-kazusa.github.io/RTmanager/>

## 安装到手机

- **Android**：Chrome 打开 → 菜单 → 安装应用
- **iOS**：Safari 打开 → 分享 → 添加到主屏幕

> iOS 必须用 Safari。从桌面图标打开 与 用 Safari 打开是两个独立的存储空间，
> 数据互不相通，请固定用桌面图标进入。

## 数据安全（重要）

数据只存在当前设备，请**定期「⋯ → 导出完整备份」**：

- 长期不打开应用时，iOS 可能清理站点存储
- 清理浏览器数据、卸载浏览器都会清除数据
- 换设备用「导出 → 导入」，**选「合并导入」不会丢数据**
- 不要更换域名 —— 数据按域名隔离存储；同一域名下换路径不受影响

## 日历：每天的人数一目了然

月度总览的每一格标注当天：

| 标注 | 含义 |
|---|---|
| **治疗 N** | 当天有 N 人安排治疗 |
| **始 N** | 当天有 N 人**开始**放疗（疗程首日） |
| **终 N** | 当天有 N 人**结束**放疗（疗程末日） |

点任意日期 → 弹层顶部就是「开始放疗 / 治疗中 / 今日结束」三个计数，
下面按类列出**具体名单**，可直接点进患者详情。

- 日历下方还有**本月汇总**：本月开始 X 人、结束 Y 人、治疗 Z 人次
- **已归档的患者也会被统计到「终」** —— 疗程结束当天往往就归档了，
  不特意处理的话「今日结束」永远是 0（这是实现时特意解决的坑）
- 患者个人日历也会标出该患者的**首日（始）与末日（终）**

## 放疗验证（可选）

有些患者在疗程中途需要做验证（位置验证、复位、中期评估等）。

`编辑患者 → 放疗验证`，或在患者详情页点「放疗验证 → 设置」：

- 填**第几次治疗时验证**，如 `10`；多个用逗号分隔，如 `10,20`
- 可加备注（如「复位+CBCT」）
- **留空表示不验证**
- 到点前会**提前 2 次治疗**进入待办提醒，办完在待办里点「✓ 标记第 N 次已验证」
- 待办里还可点「修改」直接调整，不必打开完整患者表单

> 提前 2 次是为了给排班和机器留准备时间。已标记完成的次数不再提醒；
> 若把验证次数改小了，已不存在的次数的完成标记会自动清掉，不会留下脏数据。

## 化疗与全程治疗时间轴（可选）

同一个患者往往不止接受一种治疗——可能先手术、再化疗、期间或之后放疗。

在**患者详情页**顶部有一张「**全程治疗时间轴**」卡片，把三种治疗按时间顺序串成**一条流水**：

- 点右上角「**＋ 疗程**」添加一条疗程，类型可选 **手术 / 化疗 / 放疗**
- **手术**：只记「日期 + 术式」，医院、术者、病理等写进备注
- **化疗**：以「疗程 → 周期 → 给药」三层记录
  - 疗程头点「＋ 周期」加一个周期（第 N 周期、起止日）
  - 周期卡片点「＋ 给药」记录每次用药（日期、药物、剂量、单位）
  - 给药明细**默认折叠**，点「▸ 展开给药」才展开，避免刷屏
- **放疗**：**不用手工录**。放疗事件由既有排程自动推算，与上方「治疗进度」完全一致；
  想给放疗加个名称/备注就建一条放疗疗程即可
  - 几十次放疗**默认折叠成一条段头**（显示「日期段 · N 次 · 已完成 M 次」），
    点「▸ 展开逐次」才逐条列出
  - **放疗被化疗/手术打断时会自动分段**：例如放疗 1~3 次 → 化疗 → 放疗 4~8 次 → 化疗 → 放疗 9~20 次，
    时间轴上就呈现为三段可折叠的放疗，夹杂其间的化疗各行其位

排序可在右上角切换「↓ 倒序 / ↑ 正序」，默认正序（早年→今），像病历一样从头回顾。

> **为什么放疗不手工录**：放疗已有开始日期 + 总次数 + 中断 + 加量等完整排程逻辑，
> 再录一份就会「两份数据打架」。这里只把排程结果读出来展示，保证单一真相。
> 化疗目前为**手动逐周期录入**（首版不做自动排程）。
>
> **时间轴为什么是「一条流水」而不是按疗程分块**：若按疗程分组渲染，放疗全落进放疗组、
> 化疗全落进化疗组，两者永不交错，「放疗中间掺杂化疗要分开」这条需求就永远不成立。
> 因此时间轴按日期全局排序，疗程头内联在该疗程首个事件之前，兼顾「看全程」与「就地编辑」。

## 云同步（可选，加密存到 GitHub）

`⋯ → 云同步（加密存到 GitHub）`，用你自己的 GitHub 账号做跨设备同步，**不需要服务器**。

- 云端只存**加密后的数据**，密钥和 Token 只在本机。GitHub 的 Secret Gist 并非真正私有
  （知道链接就能访问），所以加密是前提，不是可选项
- 换设备只需「同一个 Token + 同一个密码」，或粘贴云端地址
- 拉取默认走**合并导入**，两台设备各改各的都不会互相覆盖
- **患者数据与设置一起走**：节假日、调休上班日、默认治疗日、随访模板也会随云同步 ——
  它们决定排程结果，两台设备不一致会算出不同的结束日期。合并规则：
  - **取并集**：本机已有的设置不会被云端覆盖，云端新增的会并入本机
  - **删除也算变更**：删掉某个内置节日后，这个「删除」会同步到另一台设备，
    不会被云端「复活」。因为`null`（明确删除）优先级高于具体值 ——
    你「本机设了节日 A」只说明那天是假期，而删除表达的是「那天不该是假期」，
    两者冲突时必须让删除先落地，否则两边排程又会分叉
  - 老版本备份文件没有设置字段时**静默跳过**，不会被当成「设置为空」而清空本机
- 需要 https 打开才能加密（线上地址或本机 localhost，`file://` 不可用）

### 定时自动同步（可选）

`⋯ → 云同步 → ⏱ 定时自动同步`。开启后应用会**定时把本机数据备份到云端**，无需手动操作。

- **只上传、不拉取** —— 自动同步永远不会动你本机的数据，只有手动同步才会拉取合并
- **只在数据真的变过时才传** —— 没改过数据就不浪费流量、不无谓写云端；
  改了**设置**（节假日 / 调休 / 模板 / 治疗日）同样算「有变更」，会自动上传
- **间隔可自定义**：30 分钟 / 1 小时 / 2 / 6 / 12 / 24 小时（默认 1 小时，最短 30 分钟）
- **本机没有患者数据时绝不上传** —— 防止把空数据覆盖到云端
- **云端已被其他设备改过时跳过**（不覆盖、不弹窗），需要时手动「从云端拉取」后再上传
- 触发时机是**回到应用时 / 网络恢复时 / 数据停手 20 秒后**，不使用 `setInterval` ——
  移动端后台会冻结定时器，靠生命周期事件才可靠
- 需要**已保存密码**才能开启（加密必需），未保存密码时开关会被拒绝

配置步骤见设置页内的引导。Token 只需 `gist` 权限：
Classic token 勾选 `gist`；Fine-grained token 把 `Gists` 设为 Read and write。

## 四个标签页

| 标签 | 作用 |
|---|---|
| **待办** | 只提醒真正要处理的事（见下） |
| **在治** | 在治患者列表、进度、AI 导入 |
| **日历** | 月度总览：每天谁在治疗、谁开始、谁结束 |
| **完成/随访** | 归档患者与随访进度 |

### 待办只提醒三类疗程节点

为避免提醒被淹没，待办**只**保留：

- **还未开始** —— 包括已填开始日期但还没到日子、以及连排程信息都没填的
- **即将结束** —— 剩余治疗次数 ≤ 5 次
- **验证到点** —— 见下「放疗验证」
- 以及始终保留的**副反应待处理**与**随访到期**

> 「今日应治疗」「流程未通过」「疗程已结束待归档」**不再**进待办 —— 它们
> 在「在治」页和患者详情页已经看得到，堆进待办只会把真正要处理的事挤下去。

## 文件

| 文件 | 作用 |
|---|---|
| `index.html` | 应用本体，含全部界面与逻辑 |
| `manifest.webmanifest` | PWA 清单：名称、图标、启动方式 |
| `sw.js` | Service Worker：离线缓存 + 新版本提示 |
| `icon.svg`、`icon-192.png`、`icon-512.png` | 应用图标 |
| `apple-touch-icon.png`、`icon-180.png` | iOS 桌面图标（iOS 不认 SVG） |
| `.nojekyll` | 让 GitHub Pages 跳过 Jekyll 处理，空文件 |
| `README.md` | 本说明 |

数据都放在浏览器 `localStorage`（键名前缀 `radiotherapy.`），共五类：

| 键 | 内容 |
|---|---|
| `radiotherapy.v1` | 患者主数据 |
| `radiotherapy.snap.*` | 每日自动快照（保留最近 7 天，可在设置里按日期回退） |
| `radiotherapy.backup.*` | 更新前自动备份（保留最近 3 份，可回退） |
| `radiotherapy.holidays`／`.makeups`／`.tpls` | 用户自定义的节假日、调休上班日、随访模板（升级不丢） |
| `radiotherapy.sync` | 云同步配置（GitHub Token、密码、云端地址） |

> 云同步的密码默认保存在本机（可在设置里取消勾选）。**忘记密码将无法解密云端数据**，
> 且没有任何找回方式 —— 请单独记好。本机数据不受影响。

## 维护

> ### 发布是**两步**：GitHub + 项目资产
> 1. `bash dev-tools/release.sh "改动说明"` —— 应用本体上 GitHub Pages
> 2. `bash dev-tools/pack-asset.sh`，再由智能体把包上传到**项目资产（网盘）**

**发布用 `dev-tools/release.sh`，它会自动递增 `sw.js` 里的 `CACHE` 版本号（当前 `radiotherapy-v25`）、
跑完测试再推送，并轮询确认 Pages 已生效** —— 不递增版本号的话，已安装到桌面的用户会停留在旧版本。

```bash
bash dev-tools/release.sh "这次改了什么"
```

**再把完整交接包同步到项目资产**（`pack-asset.sh` 只备包，上传需智能体经 MCP 工具完成）：

```bash
bash dev-tools/pack-asset.sh        # 校验 → 打包到 /workspace/RTmanager-<日期>.zip → 快检
```

发布前会自动跑两道门禁：

- 回归测试（`dev-tools/`，共 **1,486 项断言**，19 个套件 + `qa-audit`，全部只读取 `index.html`，不修改源码）
- 兼容性门禁 `test-compat.js`（58 项）—— 拦截会让老用户丢数据或导致 PWA 装不上的改动

```bash
node test-compat.js                 # 兼容性门禁：键名 / 迁移 / 只补不丢 / PWA 资源完整
node qa-audit.js                    # 缺陷修复验收（108 项，覆盖 12 项已知缺陷）
node test-sync.js                   # 云同步全链路（模拟 GitHub API，81 项）
node test-autosync.js               # 定时自动同步（130 项，含空数据/冲突/失败等安全边界）
node test-settings-sync.js          # 设置层云同步：节假日/调休/模板/治疗日（86 项）
node test-caltodo-verify.js         # 日历人数统计 / 待办收窄 / 放疗验证 / 标签栏显隐（124 项，含按钮点击回归）
node test-course.js                 # 治疗疗程（手术/化疗/放疗）与全程治疗时间轴（101 项）
node test-*.js                      # 排程 / 迁移 / 合并 / 随访 / 模板 / AI / SW ...
node qa-perf.js                     # 渲染耗时与存储占用探针

bash scan-dates.sh                  # 跨日期扫描（必须用 bash 跑），防「只在今天绿」
```

```bash
bash pack-asset.sh                  # 打包项目资产（含回归校验，供上传网盘）
```
